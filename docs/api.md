# JSON API

## GET /api/slots

Возвращает сохранённые слоты в порядке начала. `today` — текущая календарная дата в часовом поясе переговорной. Имена и email в расписание не попадают.

```json
{
  "time_zone": "Asia/Bishkek",
  "today": "2026-11-16",
  "slots": [
    {
      "id": 1,
      "starts_at": "2026-11-16T09:00:00+06:00",
      "ends_at": "2026-11-16T10:00:00+06:00",
      "status": "past"
    },
    {
      "id": 10,
      "starts_at": "2026-11-17T09:00:00+06:00",
      "ends_at": "2026-11-17T10:00:00+06:00",
      "status": "booked",
      "booking_id": 12
    }
  ]
}
```

| Статус | Значение |
| --- | --- |
| `available` | Слот ещё не начался и свободен |
| `booked` | Слот ещё не начался и занят |
| `past` | Слот начался или уже закончился |

Поле `booking_id` есть у слота с действующей бронью, в том числе у прошедшего слота.

## POST /api/bookings

Отправьте JSON с заголовком `Content-Type: application/json`.

```json
{
  "slot_id": 10,
  "customer_name": "Анна",
  "customer_email": "anna@example.com"
}
```

- `201` возвращает `{"id":12}`.
- `400` возвращает `message`, если тело запроса не удалось разобрать как один JSON-объект.
- `422` возвращает `message` и объект `errors` с массивом сообщений по каждому ошибочному полю. Несуществующий слот считается ошибкой поля `slot_id`.
- `409` возвращает `message` с причиной, если слот занят или его время наступило.

```json
{
  "message": "Проверьте поля формы",
  "errors": {
    "customer_email": ["Введите корректный email"]
  }
}
```

## DELETE /api/bookings/{id}

При отмене возвращает `204` без тела. Если бронирования с указанным ID нет, возвращает `404`.
