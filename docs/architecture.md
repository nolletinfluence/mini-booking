# Архитектура Mini Booking

## Бэкенд

Точка входа в `backend/cmd/booking` читает конфигурацию, соединяет HTTP, бизнес-логику и SQLite. В HTTP-слое разбирается JSON и выбирается статус ответа. Бизнес-слой знает правила слотов и бронирования. Он обращается к хранилищу через интерфейс, который описывает нужные ему операции. Хранилище реализует этот интерфейс запросами через `database/sql`.

### От кнопки до базы

1. Форма отправляет ID слота, имя и email в `POST /api/bookings`.
2. Бэкенд валидирует поля. Запрос `INSERT … SELECT` ищет слот по ID и вставляет строку только для слота, который ещё не начался.
3. `UNIQUE (slot_id)` оставляет только одну запись при одновременных попытках. Если SQL не вставил строку, хранилище уточняет причину. Для неизвестного слота клиент получает ошибку поля `slot_id` с `422`, для занятого или уже начавшегося слота — `409`.
4. При `201` фронтенд снова запрашивает расписание. При `409` он показывает причину и тоже обновляет список, чтобы пользователь видел актуальное состояние.
5. `DELETE` удаляет бронь по ID. ID брони не используется повторно, поэтому поздний повтор отмены не может снять новую бронь того же слота.

### Время и сидер

Дата расписания определяется в зоне `BOOKING_TIME_ZONE`. Сидер проходит семь календарных дат, начиная с текущей, и добавляет по девять часовых слотов. Уникальные начала слотов позволяют безопасно запустить сидер повторно. При запуске завтра появятся слоты нового, седьмого дня, а прежние записи и брони останутся в базе. Расписание обновляется командой `seed`.

SQLite хранит время слотов в секундах Unix. Прошедшим считается слот с началом, равным серверному времени или раньше него. Бэкенд переводит время в зону расписания перед формированием ответа. UI показывает эти даты и часы, даже если браузер настроен на другую зону.

## Фронтенд

Структура следует Feature-Sliced Design. Верхние слои используют нижние через публичный API слайса. Страница собирает фильтр и расписание, логика брони хранит состояние диалога и запроса, модуль API выполняет HTTP-запросы. Локального состояния Vue хватает для одной страницы. [Слои FSD](https://feature-sliced.design/docs/reference/layers).

## Что показать на защите

- Запустите `migrate` и `seed`, откройте расписание и выберите завтрашний день. Забронируйте слот, затем отмените бронь.
- Покажите SQL-ограничение и тест, который отправляет конкурентные запросы. Объясните, почему отдельная проверка «слот свободен» не гарантировала бы уникальность.
- Для тренировочной правки запретите создавать бронь менее чем за 30 минут до начала. Выразите порог одной функцией в бизнес-слое и примените его при построении списка и вставке брони. Проверьте поведение на границе.
