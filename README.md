# Mini Booking

Одна переговорная, девять часовых слотов в день, с 09:00 до 18:00, включая выходные. На странице можно выбрать дату, забронировать свободный слот и отменить бронь.

Бэкенд написан на Go, интерфейс на Vue 3 с TypeScript и PrimeVue, данные хранятся в SQLite. Команда `seed` и тесты Go покрывают требования ТЗ к сидеру и тестам API в выбранном стеке.

## Запуск через Docker Compose

Нужны Docker Engine и Docker Compose. Запустите сервисы из корня проекта.

```sh
docker compose up --build
```

Интерфейс откроется на [localhost:5173](http://localhost:5173), API доступен на [localhost:8080/api/slots](http://localhost:8080/api/slots). При старте Compose применяет миграции и заполняет расписание на сегодня и следующие шесть дней. SQLite хранится в томе `booking-data`. Команда `docker compose down` останавливает сервисы и сохраняет том.

Если порты заняты, задайте `BOOKING_WEB_PORT` и `BOOKING_API_PORT` перед запуском. Чтобы добавить недостающие даты на работающем сервере, запустите сидер.

```sh
docker compose exec backend booking seed
```

## Запуск без Docker

Нужны Go 1.26+, Node.js 22.12+ из ветки 22 и npm. SQLite встроен в Go-драйвер и запускается без отдельного сервера.

Запустите бэкенд в первом терминале из корня проекта.

```sh
cd backend
go run ./cmd/booking migrate
go run ./cmd/booking seed
go run ./cmd/booking serve
```

Запустите фронтенд во втором терминале из корня проекта.

```sh
cd frontend
npm ci
npm run dev
```

Фронтенд проксирует запросы `/api` к Go через Vite. Если бэкенд слушает другой порт, запустите Vite с `BOOKING_API_TARGET=http://127.0.0.1:НОВЫЙ_ПОРТ`.

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `BOOKING_DB_PATH` | `./data/booking.db` | Путь к файлу SQLite, относительно каталога запуска бэкенда |
| `BOOKING_TIME_ZONE` | `Asia/Bishkek` | Часовой пояс переговорной, имя из базы IANA |
| `BOOKING_HTTP_ADDR` | `:8080` | Адрес Go-сервера |
| `BOOKING_API_TARGET` | `http://127.0.0.1:8080` | Адрес API для прокси Vite |

`migrate`, `seed` и `serve` должны использовать одинаковые настройки БД и часового пояса. Чтобы проверить приложение в другом часовом поясе, укажите новый файл SQLite.

## Проверки

```sh
(cd backend && go test ./... && go vet ./...)
(cd frontend && npm ci && npm run build)
docker compose config --quiet
```

Тесты проходят HTTP-обработчики с временной SQLite. Они покрывают создание, отмену и повторное бронирование, конкурентные запросы, ошибки полей и повторный запуск сидера.

## Уникальность, отмена и время

Ограничение `UNIQUE (slot_id)` в таблице бронирований гарантирует максимум одну активную бронь на слот. При конфликте вставки API отдаёт `409`. Отмена удаляет бронь, поэтому будущий слот снова можно занять. По условиям демо отмена по известному ID доступна всем.

Сидер считает календарные дни в часовом поясе переговорной. Бэкенд сравнивает моменты времени и помечает слот прошедшим, когда его начало меньше или равно серверному времени. В ответе API время передаётся в RFC 3339 со смещением, а интерфейс использует часовой пояс расписания и для фильтрации дат, и для отображения часов.

Подробности и разбор для защиты находятся в [docs/architecture.md](docs/architecture.md). Форматы запросов и ответов описаны в [docs/api.md](docs/api.md).
